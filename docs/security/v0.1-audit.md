# v0.1 pre-release security audit

## Scope and method

Review date: 2026-11-03. Initial baseline: `5c96da3`; session review was done
**last**, after preserving the partial work and rebasing onto accepted main
`775ff76b9227b2ac674d8ec28c7cebe8c8f678b7` (including the artifact lock fix).
The findings were written before their fixes. This final report records source
review, offline behavioural tests and the networked dependency review; the
handoff supplies the exact final commit and CI run IDs. No live/paid provider
requests, tags, releases, repository-setting changes or history rewriting.

The scope is the public git history and everything shipped in the CLI: sandbox,
trusted filesystem, policy/approval pipeline, credentials/diagnostics, session
maintenance, dependency licences/advisories and release tooling. Severity is
impact × likelihood for a local single-user CLI, not a multi-tenant service.
Hostile same-user host processes and kernel compromise are outside v0.1's
stated boundary. No security review proves the absence of all vulnerabilities.

Local Cargo runs were targeted and serial, using only this worktree's target/.
The full check.sh and real Linux S02 suite are delegated to exact-head CI.
The scoped Tooling ruling avoids automatic edit/LSP checks; global Pi Lens
settings were not changed. Earlier automatically started owned jobs were
stopped; other worktrees' jobs were not touched.

A01 leaves credentials and loader/startup variables in an unnecessary external
probe process; exposure impact warrants fixing even though the fixed probe script
does not normally print its environment. The probe now clears the environment
and supplies only PATH and the two user-bus connection variables it needs.
Runtime model-command launch already used a cleared environment.

A02 could persist an echoed credential or request text supplied as an error
`code`/`type`, bypassing message redaction. It now retains only an explicit
protocol vocabulary, or the transport's own `http_<status>` classification.
This is an allowlist, not a length/character heuristic: a short valid-looking
unknown string is still sensitive. Known codes and normalized error categories
are preserved, including Codex login guidance. Anthropic's existing SSE
allowlist is shared with its HTTP refiner.

A03 affects public binary distribution. Archives now include a sorted dependency
index, version-specific unmodified source download URLs, and licence/copyright
files, including the complete MPL-2.0 text and imbl copyright notices. Notices
cover the entire locked dependency set (including unused platform dependencies),
not just one architecture. Three packages omit their repository licence text in
the crate archive: jsonschema-regex uses its same-version jsonschema sibling's
MIT notice; the two winapi target packages use winapi 0.3.9's Apache/MIT notices.
These exceptions are explicit and fail closed on other missing notices. The
MPL exception applies only to the two reviewed, unmodified imbl versions; their
file-level obligations do not relicense this repository. Future dependency
changes must pass licence review and regenerate notices.

A04 is an integrity gap even without an intended mutator of immutable artifacts:
a same-size change after verification could yield a successful but unreplayable
export. The actual copied stream is now SHA-256 checked against its content
address as well as its size. A deterministic storage gate changes bytes exactly
between verification and copy; export refuses and removes its partial children.

## Full-history exposure

`scripts/history-scan.sh` walks **every reachable commit of every local/fetched
ref**, enumerates complete trees, and scans each unique blob once, retaining a
representative containing commit, blob ID, path and line. It also scans all
commit identities and messages. This includes removed files and side branches;
it is not a HEAD-only grep or a first-parent diff. Shallow repositories are
refused. Exit zero means scan completed, **not** credential clearance. Matched
values are never printed or stored in the audit output. `test-history-scan.sh`
proves removed/side-branch coverage, entropy context, value suppression and
shallow refusal using clearly synthetic markers only.

The recorded review covered **605 commits**, with **1,790 candidate locations**
(a location/category is counted once per unique blob, or per metadata line).
`history-hits.tsv` classifies every one without reproducing matched values:

| Classification | Count | Explanation |
| --- | ---: | --- |
| True positive, noncredential | 34 | Non-GitHub-noreply commit identities or messages, including tool-generated noreply identities |
| Sanitized fixture | 190 | Hand-built example journals/goldens, API/SSE fixtures and synthetic authentication fixtures/scaffolding |
| False positive | 1,566 | Implementation/schema field names, token-budget/job-token identifiers, scanner patterns, public references, virtual sandbox HOME |
| True positive credential | 0 | No credential requiring rotation identified |

Categories overlap: credential context 1,421; auth/account context 138; local
paths 7; email 38; recording context 155; entropy context 31; credential-shaped
keys 0. The seven home-path hits are **virtual `/home/sandbox/`** paths in
sandbox tests, not a person's host home. Four non-metadata email hits are the
same deliberately invalid example URL across fixture revisions, not accounts.
Entropy hits are synthetic sentinel/refusal-test strings and code identifiers,
not unexplained keys. Account/auth JSON mentions are implementation vocabulary,
paths to a login file, and synthetic fixture data, not a committed real login.
The one recorded Codex SSE fixture was checked against its lossy recorder:
IDs, content, state payloads and usage counts are substituted **before writing**.
The other SSE/JSONL fixtures are synthetic. No raw live transcript was found.

This is heuristic discovery followed by review, not exhaustive detection of all
possible encodings. Subsequent audit-source additions are scanned again before
handoff; the checked-in inventory is a bounded historical evidence snapshot,
not a recursively self-updating manifest of its own commit. On discovery of a
true credential, stop and report only its commit, path and kind; rotation and
rewriting remain the owner's decision.

## Trusted file boundary

Reviewed `tools/fs/{mod,resolve,execute}.rs` and `WorkspacePath`/planning.
Resolution is rooted in a pinned descriptor with openat2 BENEATH,
NO_SYMLINKS, NO_MAGICLINKS and NO_XDEV, with **no fallback**. Reopens use the
full relative prefix and recheck object/ancestor identities and protection.
`.git` is read-only; configured protections and an in-workspace data root are
denied by policy and inode identity. File mutations require regular single-link
files, recheck preimages, stage a same-parent exclusive temporary, fsync, strip
special permission bits and atomically rename; absent targets use NOREPLACE.

The existing suite tests final/intermediate/magic links, swapped ancestors,
relocation outside the root, root-name replacement, hard links (including links
to outside files and links introduced after planning), cross-mount denial and
cancellation at precommit steps. `list_directories` is bounded, lexicographic,
non-symlink-following and revalidates the opened directory/ancestors after walk.
New tests add FIFO and real character-device refusal without requiring root,
and overlong component/path cases. ENAMETOOLONG now maps to `too_large`.

User config/instructions outside the workspace use their explicit user-owned
file boundary, not project policy. User instruction/config symlinks can be
followed; project instruction discovery cannot. Do not put secrets in instruction
files: instructions become recorded context by design.

## Policy, approvals and prompt injection

The registry and opaque validated operations/plans cannot be deserialized from
model JSON. A pending approval binds its ID, canonical plan digest and policy
revision, expires after five minutes, and executes the stored plan rather than
resubmitted arguments. Changed policy, wrong digest, stale tokens and reused
tickets fail closed. Intent/authorization are durable before dispatch.

Remember derives only an exact tool/path, or exact bash command and cwd; it
cannot override denied capabilities/protected paths. Configuration revision
changes invalidate tickets. `approve_read_only` is ask-only and requires the
registry's exact read effect and TrustedFs backend plus an available terminal;
the TUI still requires explicit keys. Read-only approval includes readable
workspace metadata such as `.git`; it is not a secret-content detector.
Remembered grants are not silently imported on continuation; client refusal is
an availability/UX limitation, not permission to drop the allowances comparison.
History remains available to read-only inspection and export.

Only the user config location/explicit flag is read, with bounded strict TOML
keys and credential-key refusal. There is no project config or policy key in
user TOML. Nested AGENTS.md is framed instruction text, not parsed configuration.
Tool output, file content, project/user instructions, native provider state and
compaction summaries can all influence **model context and proposed calls**.
None can install registry tools, change trusted capability policy or submit an
approval. Anthropic-compatible APIs merge developer instructions into their
single system field: this amplifies injection influence on proposals but does
not cross the execution authority boundary. Review proposals before approving.

## Credentials, diagnostics and session maintenance

Production credentials originate only from environment or a bounded,
owner/mode-checked, NOFOLLOW Codex auth file. Debug/Display redact credentials;
headers are sensitive, retries/redirects/ambient proxies are disabled, transport
errors are fixed classifications and provider messages are not echoed.
A02 closes the separate provider-code channel. No credential is part of logical
requests, tool environments, configuration artifacts or ordinary errors.

`security_audit` sends an artificial credential to an attributed loopback fixture,
which confirms the actual request header and deliberately echoes the value in
HTTP/SSE code/type and message fields. It checks real durable journals and
artifacts, both Markdown/all-branches and journal exports, actual diagnostic
banner/transcript rendering, and config-show refusal stdout/stderr. It checks
0700 data/export directories and 0600 journals, artifacts and Markdown outputs.
The older process sentinel test retains environment/Codex failure coverage;
provider tests retain Debug, body/header and panic-output coverage. No real
credential, external provider request or user's auth file is used.

A transcript is not a general-purpose secret scrubber: user/model/tool text is
preserved verbatim. A key pasted into an ordinary model-name/path field or into
workspace content may be printed/recorded like any other user content. Export
preserves the journal faithfully; it must not silently rewrite history. Inspect
exports and doctor output before publishing them.

Session review on 775ff76 confirms pinned private directories, typed IDs/digests,
NOFOLLOW/NONBLOCK opens and private single-link files. Delete takes the exclusive
journal lock and removes **only the journal**. GC first validates every journal
under shared locks and refuses unreadable/locked/corrupt journals; it retains all
referenced and younger-than-24-hour artifacts, ignores unsafe objects, and
unlinks only content addresses relative to the pinned artifacts directory.
An independent-description artifact flock serializes selection/unlink with
publication/dedupe refresh. The accepted deterministic race regression was rerun.

Exports refuse existing/symlinked final outputs via mkdir/EXCL or NOREPLACE;
A04 now verifies the actual copied checksum. Explicit user-selected parent paths
can contain symlinks (not workspace resolution). Partial journal export failure
removes created children but may leave an empty destination directory; it never
removes pre-existing output. This is low availability/cleanup risk, not an
escape. The maintenance suite checks reference/grace retention, unsafe journals
and artifacts, dedupe refresh, dry run, source byte preservation and export
replay. New tests assert symlink output refusal and creation permissions.

## Supply chain and release integrity

Installed `cargo-audit 0.22.2` and `cargo-deny 0.20.2` with `cargo install --locked`
in a temporary CARGO_HOME/root under this worktree target/, serially. Tools and
temporary generated directories are removed after validation. Advisory database
revision: `965bf9ad083b58e6340d65829d85217b18be9290`.

- **cargo audit:** zero vulnerabilities. One informational advisory:
  **RUSTSEC-2025-0141**, bincode 1.3.3 unmaintained. Syntect decodes trusted bundled
  syntax dumps, not arbitrary model-supplied bincode. No patched version exists;
  this is recorded as low maintenance risk, with an explicit reasoned exception
  in deny.toml (not a suppressed vulnerability).
- **cargo deny:** advisories, licences, bans and sources pass. Seven duplicate
  families are warnings: base64, fancy-regex, getrandom, hashbrown, r-efi, syn,
  windows-sys. They are distinct transitive semver/platform requirements, not
  unreviewed alternate sources. Registry/git sources fail closed, no unknown git
  sources are allowed; wildcard exceptions apply only to local workspace paths.
- MIT/Apache-compatible permissive licences are allowlisted; only reviewed imbl
  7.0.2 and imbl-sized-chunks 0.2.0 have MPL-2.0 exceptions, with distribution
  notices and corresponding source links. There is no broad copyleft allowance.
- `scripts/supply-chain.sh` is explicitly networked/opt-in, not in check.sh.
  `--install` installs pinned tools temporarily and cleans them up. The separate
  weekly/manual workflow has read-only permissions and does not add a required
  check or hide its failure with continue-on-error.

Release review found no injection-shaped expression in run steps: refs and
other dynamic values use env indirection and quoted expansion. Only tag-push
publish has contents:write; workflow_dispatch cannot publish, nor can PR CI.
Third-party actions are SHA-pinned and checkout credentials are disabled in the
release/supply-chain workflows. Version/tag matching precedes builds; two native
musl targets are smoke-tested, archives independently check required members,
normalise ordering/modes/ownership/timestamps/gzip metadata and compare bytes.
The new notices are part of those same reproducibility checks. No tag/release or
paid/dry-run binary build was initiated by this audit.

## Residual risks and post-v0.1 work

- No seccomp; TasksMax depends on a usable user systemd manager. Uninterruptible
  kernel I/O can delay cleanup indefinitely; returning early would falsely claim
  descendants are gone. No unrestricted fallback is acceptable.
- Shell binds protect names, not all hard-link aliases; mount setup does not
  provide trusted-file descriptor guarantees against hostile concurrent host
  mutation. Root renames can diverge pinned file tools from path-bound shell.
- Absent protected paths cannot be masked; creation is detected after execution
  without rollback. An initially absent `.git` is not mounted read-only, so git
  initialization is possible in that first command. Existing `.git` is protected.
- Probe/bwrap diagnostics and session headers can contain user-selected host
  paths. User instructions can follow user-owned symlinks; do not store secrets
  there. Read-only authority is not content redaction.
- Remembered-grant continuation now names its reason in `ask` and resumes in the
  TUI; neither path weakens policy or journal checks.
- Release provenance/attestations, signatures and independent reproducible binary
  builds remain future hardening. Archive reproducibility alone is not that proof.
